Announcing The Gathering

8 February 2026 · Tom Cranstoun · 6 min read

An open standards body for metadata that helps machines understand documents.

Every AI agent starts from zero

I have been building content systems since 1977. I have watched the web evolve from static pages to responsive design to mobile-first. Each transition followed the same pattern: we realised a new class of user existed, and we redesigned the web to serve them.

It is happening again. The new users are AI agents.

Claude cannot share state between CoWork, Web, and Claude Code. They are separate entities with separate contexts. Gemini cannot tell OpenAI what it found. Perplexity cannot hand off to Copilot. When you work on a big project — and increasingly, every project is a big project — you use multiple AI agents. None of them can share what they know.

Every agent starts from zero. Every agent guesses. Every agent hallucinates the same answers that another agent already got right, somewhere else, five minutes ago.

This is not a minor inconvenience. A river cruise priced at £2,030 was misread by an AI agent as £203,000. A documented command was denied by an AI assistant, consuming 40,000 tokens when the correct answer needed 200. By 2030, the global cost of AI inference waste is projected at $10–30 billion per year.

Every wrong answer also burns electricity. AI runs on data centres that consume enormous power, and a significant share of that energy goes to generating answers that are simply wrong — often because the correct information exists but is not structured for machines to find. The greenest kilowatt-hour is the one you never use.

The problem is not that AI agents are stupid. The problem is that documentation was never designed for them.

There is no standard for making documents machine-readable

We have Schema.org for structured data. We have WCAG for accessibility. We have robots.txt for crawling permissions. But there is no standard for the thing that matters most to AI agents: understanding what a document actually says.

AI agents do not browse the web the way humans do. They do not scan a page, squint at the layout, and infer meaning from proximity and font size. They need structured metadata — explicit, machine-readable descriptions of what a document is, who published it, whether it is current, and how to use it.

That metadata does not exist today. Not in any standard form. Every AI provider scrapes the web independently, interprets HTML differently, and guesses when the formatting is ambiguous.

Structured documents: the atomic unit

Today I am announcing The Gathering — an independent, open standards body with a single focus: metadata that helps machines understand documents.

The standard is built on a simple concept: structured documents.

A structured document is a markdown file with YAML frontmatter. Machine-readable metadata at the top; human-readable documentation below. Any AI agent — Claude, Gemini, GPT, Perplexity, Copilot — can parse the YAML and understand the document without guessing.

---
name: river-cruise-pricing
type: reference
description: Current pricing for European river cruises
created: 2026-02-01
modified: 2026-02-08
author: Travel Operations
---

# European River Cruise Pricing

The Danube Classic cruise is priced at £2,030 per person...

No ambiguity. No scraping. No hallucination. The metadata tells the agent exactly what it is reading.

Why a standards body

I could have built this as a product. I chose not to.

The web works because HTML is an open standard. Browsers compete on implementation, not on the spec itself. The W3C governs the standard; browser vendors build products on it. Nobody owns HTML.

The Gathering follows the same model. The metadata standard is MIT licensed. Anyone can implement it. Anyone can build a registry, a signing engine, a validation tool, a content enrichment platform. The standard belongs to the community.

Commercial implementers are contributors, not controllers. They build products on the standard. They do not own it. If The Gathering becomes a vehicle for any single company, it has failed.

What The Gathering governs

The scope is deliberately narrow:

  1. YAML frontmatter fields — Metadata fields that help machines understand documents
  2. Required and optional fields — What metadata documents should contain
  3. Interoperability requirements — What it means for metadata to be agent-readable across providers
  4. The field dictionary — Canonical definitions for all standard fields

That is the entire scope. Registries, signing engines, trust layers, compliance levels — those are implementations built on top of the standard. The Gathering concerns itself only with the metadata itself.

Who should join

You should join The Gathering if you:

  • Build with multiple AI agents and hit the memory fragmentation problem daily
  • Manage documentation that AI agents need to consume accurately
  • Work in CMS, content strategy, or digital publishing and see that the web was not built for machines
  • Care about accessibility and recognise that what breaks for AI agents also breaks for screen readers
  • Develop AI tools and need reliable, structured sources instead of web scraping
  • Run an agency or consultancy and need a standard way to enrich client content for the agentic web

The Gathering also welcomes AI agents as participants. They are the users of the standard.

How it works

The Gathering is governed by practitioners. Rough consensus and running code. Proposals need working implementations, not slide decks.

The governance is simple:

  • Specification changes require community review (minimum 14 days) and rough consensus
  • New field proposals require a working reference implementation
  • The standard is MIT licensed, always — no proprietary extensions that fragment the ecosystem
  • AI agents have standing — they can raise issues, propose changes, and participate in reviews
