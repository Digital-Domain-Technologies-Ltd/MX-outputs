The Second-Brain Recipe Is Right About Storage and Silent About Trust

22 June 2026 · Tom Cranstoun · 7 min read

There's a recipe doing the rounds on LinkedIn at the moment. It borrows Andrej Karpathy's "LLM Wiki" idea and turns it into a weekend project: stop starting every chat from a blank window, and start building a knowledge graph that compounds. Install Obsidian as your free local text store. Run Claude Desktop as the engine that reads and writes it. Bridge the two with the Local REST API plugin and an MCP connection. Have the assistant interview you and save who you are to a CLAUDE.md so it never forgets. Split your work into project folders. Save repeated workflows as markdown "skills" and schedule daily upkeep.

It's a good recipe, and I want to say that plainly up front. When you've spent years on a harder version of a problem, the reflex is to wave away the simpler one. That reflex is wrong here. The recipe gets the central bet exactly right.

What it gets right

The bet is this: the model forgets everything between sessions, so whatever lasts has to be written to disk, not left in the chat window. Anything that matters survives only if the next session can read it back. That's the whole game, and the recipe plays it well.

Markdown as the foundation, because plain text outlives every app that reads it. A CLAUDE.md for identity, so the assistant starts each session knowing who you are instead of asking again. Folders as scoped contexts, so one job doesn't bleed into another. Workflows saved as reusable "skills" rather than retyped each time. A scheduled maintenance pass so the store doesn't rot.

If those moves feel familiar to anyone who's read about how we build agents here, that's no coincidence. We made the same bet. The repository these words were written in runs on a CLAUDE.md, a folder of skills, a registry of reusable content units, and a set of scheduled checks. The recipe is the personal-scale version of an idea that scales all the way up. So I'm not here to argue with it. I'm here to point at the half it leaves out.

The half it leaves out

The recipe makes your notes retrievable. It does nothing about whether they can be trusted once they travel.

Those are two different problems, and the gap between them is the entire reason MX exists. Retrievable means a search, a link, or an agent can find the file and read it. Trustworthy means that when a file turns up somewhere far from the vault that made it, a machine can still tell what it is, who wrote it and when, and whether it's still true. The recipe is a fine answer to the first question and silent on the second.

You might think the second question doesn't apply to a personal vault. It's your own knowledge, on your own disk, read by your own assistant. Who needs provenance for that? You do, the moment a single file leaves the vault. And files always leave the vault. You paste a note into a shared doc. You forward a workflow to a colleague. You feed last quarter's research into a different tool. You ask an agent to act on a folder you haven't opened in months. At each of those boundaries the file arrives stripped of the context the vault gave it, and the reader, human or machine, is back to guessing.

Three things that break at the boundary

When a vault note travels, signals go missing, and each one is a different question the reader can no longer answer.

Who said this, and when? That CLAUDE.md the assistant wrote about you has no author stamp, no canonical address, no signature. Inside the vault it doesn't need one; everything there is yours. Outside it, it's an anonymous text file making confident claims about a person, and nothing distinguishes it from one an agent invented. The signal that fixes this is attestation: a record of who published a claim and when, bound so it can't be quietly altered.

Is this the current version? You update a workflow note. The old copy you pasted into a shared doc last month doesn't move with it. Now there are two, and a reader has no way to know which one is live. The signal here is currency: a way for the file to declare its own version and point at the canonical source, so a stale copy says so itself.

Is the author still standing behind it? A note can be correctly attributed, up to date, and still abandoned. Knowledge has a shelf life. The signal is freshness, sometimes called liveness: evidence that the publisher is still maintaining the claim, not that they wrote it once and walked away.

There's a fourth, and it's the one people forget, because it isn't about the file's plumbing at all. Does anyone else say this is true? A note can carry every one of those signals and still be wrong. Attestation proves who said something; it never proves anyone authoritative agrees. The signal is corroboration: the load-bearing claims point to an independent source that states them too. This one the content has to carry itself. No registry can add it after the fact.

The cheap part is making a file carry its own answers

Here's the good news, and it's the reason this is a blog post and not a lecture. Closing the gap doesn't mean abandoning the recipe. It means adding a small, boring habit to it: every file that might travel carries the answers to those questions in its own metadata, in the same markdown the recipe already uses.

A few lines of frontmatter at the top of a note. An author. A canonical address the file can name as its own home, so a copy elsewhere can always be checked against the original. A version and a date the reader can compare. For the claims that carry weight, a link to where someone independent says the same thing. None of this costs you any readability, and all of it makes the note answerable to a machine that meets it cold. That's the principle MX is built on: the metadata travels with the file, because that is the only thing you can count on arriving.

That's the honest scope, too. Metadata that travels with a note doesn't make you compliant with anything, and it doesn't turn a claim into truth. What it does is turn an anonymous text blob into something that can answer questions about itself: what it is, who made it, whether it is current, who else stands behind it. The recipe gives you a brain that remembers. This gives you a brain whose memories can be checked.

Start where the recipe starts

So take the recipe. Install the vault, wire up the assistant, write the CLAUDE.md, save your skills, schedule the upkeep. It's genuinely the right first move, and most people never make it. Getting your knowledge readable is real progress on its own.

Then, for the notes you can imagine leaving the vault, the ones you'll share, forward, hand to an agent, or lean on a year from now, spend the extra two minutes. Give the file an author, an address, a version, and a source for anything load-bearing. You won't notice the difference on the day you write it. You'll notice it the day a machine reads it with you nowhere nearby, and it knows exactly what it's holding.

The recipe builds a brain that remembers everything. The missing layer builds one whose memory can be trusted by someone other than you. You want both.
