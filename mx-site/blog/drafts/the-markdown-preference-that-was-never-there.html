The Markdown Preference That Was Never There

11 June 2026 · Tom Cranstoun · 6 min read
  • Markdown
  • Content Negotiation
  • Agents
  • Tokenisation
  • Governance
  • Mx

A while ago I wrote about The Markdown Trap: what a governed web page loses when an agent asks for it in markdown instead of HTML. That post treated the loss as the problem and stopped there. Nic Gould (2026) has since published something that goes underneath it, and it changes how I would now argue the whole case. His title is blunt: your agent does not "prefer" markdown. He is right, and the reasons are worth walking through, because the phrase he is taking apart is quietly steering real decisions.

"Agents Prefer Markdown" Is Doing a Lot of Work

The claim has hardened into received wisdom. Markdown is clean, lightweight, human-readable, so of course an agent finds it easier to consume. It sounds right. Teams are now choosing document formats, designing data contracts, and building pipelines around it.

The trouble, as Gould puts it, is that there is no evidence for the preference, and it falls apart the moment you look at what the model actually receives. The belief survives because nobody checks it. It feels true, and feeling true is enough to ship a design decision.

The Model Never Sees the Format

Here is the part that does the damage to the meme. A language model never sees your markdown or your HTML. It sees tokens.

Before any text reaches the transformer, a tokeniser converts it into a sequence of integer IDs using byte pair encoding. The model receives a list of numbers. There is no flag that says "this was markdown" or "this was HTML", no format-aware preprocessing, no special handling. As Gould draws it: the model never knows it was markdown.

The one real nuance is that the tokeniser itself carries format familiarity. Byte pair encoding builds its vocabulary by merging the character pairs that appear most often in the training data. Common HTML fragments like <table> and <h2> turn up so frequently on the web that they collapse into single tokens or very short sequences. Markdown markers like ## and ** are learned just as well. By the time the model is reasoning, both formats have already dissolved into familiar tokens.

So "prefer" is the wrong verb before we even get to the evidence. Preference implies perception, and the format is gone before the model wakes up.

Two Axes That Keep Getting Confused

Gould's sharpest move is to separate two things almost every argument runs together.

Token efficiency is about how many tokens it takes to represent the same content. Leaner formats win here, fewer closing tags, fewer attributes, less syntactic overhead. For document-style prose, markdown is genuinely lighter than HTML. For structured data the gap swings the other way depending on the serialisation you pick. This is the axis the markdown advocates are standing on, and on this axis they are often correct.

Semantic comprehension is about how well the model understands the meaning and structure of what it read. This is where the received wisdom inverts. Gould points to the Table Meets LLM benchmark (Sui et al., 2023, as cited in Gould, 2026), which tested comprehension across input formats on a set of structural tasks. HTML scored highest overall, a little over sixty-five percent, several points clear of the rest. The format we are told agents find "harder to consume" produced the best comprehension.

Read those two axes together and the popular sentence collapses. Markdown can be cheaper to read and worse to understand at the same time, and the "agents prefer it" claim quietly swaps the second virtue in for the first.

The Third Axis the Meme Hides

There is one more axis, and it is the one I care about most, because it is where MX lives. Gould did not need to make this point for his argument. I need to make it for mine.

When the edge rewrites a governed HTML page into markdown, the prose mostly survives. What dies is the machine-readable governance layer: the content-policy declaration, the attribution requirement, the discovery links an agent follows to find the rest of the site, the structured data that an HTML parser treats as authoritative and a markdown reader sees as a fenced code sample. I measured one of those conversions in The Markdown Trap, and the bytes that disappeared were almost entirely that layer.

So for a governed page, markdown is not merely cheaper-and-maybe-worse-at-comprehension. It deletes the part of the page that the page exists to carry. The words come through. The instructions about what you may do with the words do not.

Where the "Preference" Actually Comes From

If no agent perceives the format, where did the preference come from? It is a tooling default wearing a personality.

Look at what agents send on the wire. Most send Accept: */*, which means "give me anything." Some send Accept: text/markdown, */*, which puts markdown first but ends in a wildcard that will happily take whatever the server returns. A minority express a genuine weighting with quality values. None of that is a preference in the way the meme implies. It is a fallback order in a request header, and the server still decides what actually comes back (Checkly, 2026; Cloudflare, 2026).

The agent is not reaching for markdown because it reads better. A default header lists it first, and a CDN feature offers to provide it. We then narrate that arrangement as the machine's taste.

What This Changes

For publishers, the move is the same one I argued before, but now it rests on firmer ground. Serve HTML for governed pages regardless of the Accept header. You are not overriding the agent's wishes, because it has none here. You are answering a wildcard with the richer representation, the one that still carries the governance layer when it lands.

For people building agents, treat Accept: text/markdown as a task-scoped choice, not a global default. When the task is "read this prose", markdown is fine. When the page might carry policy, discovery links, or structured data, ask for HTML and parse it. Reading HTML is cheaper than discovering later, through a missed attribution or a broken discovery chain, that you read the stripped copy.

And for anyone writing about this, retire "agents prefer markdown." It misdescribes the machine, and the misdescription is leaking into format and contract decisions that will be expensive to unpick.

The MX Version of the Sentence

We encode this belief in our own metadata, and I had it wrong. An agent profile that declares a markdown "preferred access" is asserting a preference the agent does not have, and pointing it at the format that strips the governance layer. The honest field does not describe the agent's taste at all. It states what the publisher serves and why: HTML, so the machine-readable layer survives the trip. I am fixing ours.

The preference was never the agent's. It was ours, projected onto a system that reads in tokens and acts on whatever we hand it. So hand it the richer thing.
