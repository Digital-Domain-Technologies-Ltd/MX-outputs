Your Agent Can Draw Now. The Picture Should Say So.

25 June 2026 · Tom Cranstoun · 5 min read

A tip is doing the rounds this week, and it is a good one. If you let your coding agent generate images while it builds a web UI, and use those images as real assets rather than reaching for stock, the pages stop looking bland. The writer's reasoning was sharp: a chat-only coding assistant cannot draw, so its output tends towards the same flat, text-heavy look everyone now recognises as AI-built. Hand it the ability to make pictures and the work feels different.

I agree, and I wired it into my own toolchain the same day. But the moment I did, a different question took over, and it is the one this whole project exists to ask. A generated image is an AI action. Where does that action get recorded?

The file that cannot say what it is

Think about what actually lands on disk. An agent reads your prompt, calls a model, and writes a PNG into your assets folder. To the page, it is just an image. To the next system that meets it, a content management import, an accessibility checker, a partner ingesting your media library, a regulator asking how a published asset was produced, it is also just an image. Nothing on the file says a machine made it. Nothing says which prompt, which model, or when. The picture looks great and remembers nothing.

That is the same gap I keep writing about from different angles. A delay is what you build when you cannot verify provenance on the spot. A bland page is what you ship when your agent cannot draw. And an anonymous PNG is what you get when image generation treats "make it look good" as the whole job and "record what just happened" as nobody's job. The prettier the output, the easier it is to forget that an AI produced it.

What I built instead

So the image generator I added to the MX toolchain does the pretty part and the honest part in one pass. It runs against a Stable Diffusion server on local hardware, over localhost, with no hosted API in the path at all. That is a deliberate choice and not only a privacy one: for the regulated clients we work with, an image pipeline that sends prompts to someone else's cloud is a non-starter, and an air-gapped one can run where the data has to stay.

When it writes the file, three things happen that a bare generator skips. The call tees to a local AI-action log, so there is a dated record of the prompt, the model, and the parameters that produced this asset. The image is decorated with MX metadata in its own carrier, travelling with the file rather than sitting in a database someone has to be trusted to query. And the metadata carries an explicit mark: this asset was AI-generated. A machine that opens the file later can read that in the time it takes to parse a header. It does not have to guess, and it does not have to ask us.

Why the mark matters beyond good manners

Marking AI-generated content is not a courtesy that will stay optional. The European Union's AI Act, in Article 50, sets transparency obligations that point squarely at this: systems generating synthetic image, audio, video, or text are expected to mark their outputs as artificially generated or manipulated, in a form a machine can detect. The industry is building shared plumbing for the same idea; the Coalition for Content Provenance and Authenticity has a standard for exactly this kind of travelling provenance. The direction of travel is clear, whichever instrument reaches you first.

The point is not that one library makes you compliant. It is that the cheapest moment to record an asset's AI origin is the instant the asset is born. Backfilling that mark across a media library nobody labelled is the expensive, lossy job you do later under deadline. Mark it at birth and the record is just there.

What this does not claim

Let me be straight about scope, because overclaiming is how this whole field loses trust. A machine-readable mark does not prove the image is accurate, safe, or rights-cleared. It proves one specific thing: that the asset declares its own AI origin, honestly, in a form a machine can check without taking our word for it. That is a small claim, and it is exactly the claim the metadata is entitled to make. The judgement about whether the image is fit to publish still belongs to a person.

The lesson is the same one that runs through everything we build. Making content readable to machines is the floor, not the ceiling. The trend that started this, agents drawing pictures so pages look less generic, is real and worth adopting. Just remember that the file your agent drew is doing two jobs now. It is decorating your page, and it is a record of an AI action. Build the pipeline that lets it tell the truth about the second job, and the first one costs you nothing extra.
