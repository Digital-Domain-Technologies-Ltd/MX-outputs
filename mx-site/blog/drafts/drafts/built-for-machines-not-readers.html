Built for Machines, Not Readers

4 June 2026 · Tom Cranstoun · 4 min read

An audit I ran recently would not finish. The crawler started, fetched a few pages, then sat there. Not blocked, not throttled. Reading. The site's sitemap was feeding it more URLs than it could swallow, and it kept asking for more.

I have anonymised the site. The pattern is the point, and the pattern is not rare.

The Sitemap That Would Not End

When I looked at what it was reading, the shape was clear. The sitemap was not a list of pages. It was an index of other sitemaps, two dozen of them, most a fixed block of exactly ten thousand URLs. Add them up and the site declared close to a quarter of a million pages.

Four of those sub-sitemaps held the site's own material: a homepage, an about page, a contact page, a set of technology pages, a set of comparison pages, a few blog categories. The rest held profiles. One page per external domain. Hundreds of thousands of small, templated pages, each describing somebody else's website.

Fetch the index twice and the count moves. It is generated on request, and the number of shards drifts between requests. Nothing here is a static file a person edits. It is output.

Pages No Human Can See

I tried to open one. A bot-protection challenge answered: a holding page, no content, a refusal to anything that was not a full browser running scripts. I tried again with headless Chrome. It passed the check and still could not reach the page in any reasonable time.

So the quarter-million pages in the sitemap are not served to a reader who clicks a link. They are gated.

Then I read the robots.txt. It named GPTBot, ChatGPT-User, OAI-SearchBot, ClaudeBot, Google-Extended, PerplexityBot, and several more, and it allowed every one of them into the gated path. The wall is for people. The door is for machines.

The Inversion

robots.txt was built to keep crawlers out. A publisher listed the paths a bot should not touch, and well-behaved bots obeyed. The file was a fence.

This file is the opposite. It is a fence against humans with an invitation pinned to it for the AI crawlers. The pages exist so that a model will ingest them and, later, cite them. They do not exist so that a person will read them. A human who finds one gets a security check. A language model gets the full text.

That is not an accident of configuration. It is the design.

Built for Machines, Not Readers

This is programmatic SEO pointed at language models. Generate one page per entity, a quarter of a million of them, each a thin template with the data swapped in. Keep humans out, so the pages never have to survive a real reader. Let the crawlers in, so the volume lands in training data and retrieval indexes.

The technology and comparison sections were the same move at a smaller scale: thousands of pages, one per tool, one per pairing, all generated from a single source list.

None of it is illegal. Most of it breaks no platform's rules. But it is a bet about what the web is now for. The bet is that breadth wins: that a model asked about a domain reaches for the page that exists rather than the page that is good, and that existing in volume beats being worth reading.

What the Audits Keep Finding

I have started keeping a record of these. Not the scores, the oddities: the sites whose machine-readable surface is built for ingestion rather than for reading. A picture is forming, and it is not the web most people think they are using.

There is a name worth giving the shift. The old web was written for human eyes, and search indexed it as a byproduct. Now a second web is going up over it, written for machines to ingest, with humans as the byproduct this time. An audit is one of the few places you can stand on the seam and see both at once.

The Part That Matters

If you build for machines, and increasingly everyone does, the question is not whether to. It is what you put behind the door.

A quarter of a million templated profiles is breadth without depth. An agent that reads them learns that a page exists, not that what it says is true. The answer is not less machine-readable content. It is machine-readable content worth citing: claims that carry their provenance, entities that resolve to real identifiers, statements an outside party can verify without having to trust the publisher.

That is the whole of MX in one line. Build for the machine. Then build something the machine can stand behind.
