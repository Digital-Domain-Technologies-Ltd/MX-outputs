The estate is the argument

3 July 2026 · Tom Cranstoun · 5 min read

This morning a file was about to go live broken, and the repository stopped it.

The file was a short declaration about how AI was used in writing our books. On my machine it read perfectly. It was a shortcut, a pointer to the real file one level up, and locally that pointer resolved to exactly the right place. But the live site is built from a copy of one folder, on its own, with nothing above it. In that copy the pointer led nowhere. The file would have shipped as a broken link on a public page, and I would not have known until someone told me.

I did know, because a check caught it before the push. And once it was caught, I did the thing the repository is built to make me do: I did not just fix the file, I wrote the check that makes the mistake impossible to ship again. The next broken pointer of that kind now fails the push, loudly, with the reason attached.

That small event is the whole argument in miniature.

A standard is only as honest as the thing that carries it

MX is a practice for making content legible to machines. It says: a file should carry its own account of what it is, where it came from, and how it may be used, so that a machine meeting the file outside the system that made it does not have to guess.

That is easy to write in a specification. It is harder to live. Most standards are described in a document and then quietly contradicted by the thing that ships them, a website that preaches structure and serves a wall of undescribed markup, a governance framework published as a PDF with no machine-readable trace of its own rules.

So the fair test of MX is not the specification. It is the repository that carries it. If that estate is itself illegible, unchecked, and vague about its own state, the standard is a claim. If the estate is legible, self-checking, and honest about what it is at any moment, the standard is a demonstration you can read.

Self-describing, self-checking, self-healing

Three properties do the work, and the broken file touched all three.

It is self-describing. Every file in the estate carries its own metadata: what it is, who wrote it, what it depends on, how it should be handled. That is not decoration. It is what lets a check reason about a file it has never seen before, and it is what let the repository know that a served page had a dependency reaching outside its own boundary.

It is self-checking. The rules are not advice in a document that someone remembers on a good day. Each one is a script that runs before a push and refuses the push when the rule is broken. The estate will not publish content whose source has quietly moved since it was prepared. It will not commit a secret, or a file from outside its own tree. And now it will not ship a served file that points at something the live build cannot see. The check is the rule. Everything else is just describing the check.

It is self-healing, but only where it can see its whole self. The estate regenerates its own indexes and repairs its own drift, and it refuses to do either from a partial copy, because healing from half a view heals wrong. Self-awareness is what guards self-healing. A repository that does not know what it is has no business rewriting itself.

None of this is aspiration. It is the ordinary condition of the estate on a normal Tuesday, enforced the only way a rule can be trusted: by a machine that fails loudly when the rule is broken, not by goodwill.

Put those three together and you have more than content that describes itself. You have content that manages itself. The metadata is not a label stuck on the outside; it is what the estate reads to check its own work and repair its own drift. Description the system acts on becomes self-management, and that is the win: a repository that runs on its own account of what it is, and holds that account true.

Why this is the sell

When we tell an organisation that MX will make its content legible and its governance verifiable, the reasonable response is: prove it. Not with a slide. With the thing itself.

The estate is that proof. It is a working example of content that describes itself, rules that enforce themselves, and a system that is honest about its own state at every moment, because it cannot push a change that would make it dishonest. A buyer does not have to take the standard on faith. They can read the repository and watch it refuse its own mistakes.

That argument runs in the estate: the specification holding itself to its own rule, catching a broken file on an ordinary morning before anyone else could.

The estate is the argument. Everything else is just the description.
