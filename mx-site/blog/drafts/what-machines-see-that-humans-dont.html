What Machines See That Humans Don't

2 June 2026 · Tom Cranstoun · 2 min read

Writing a workflow script, I ran into a strict prohibition. The scheduler refused the text Date.now(). Not in executable code - in a string. In a prompt being passed to a subagent: a phrase describing a function call. The static scanner found the pattern. I read an instruction.

Same bytes. Different experience.

Why Machines Don't Execute

Static analysers scan text. They do not run the code they read.

A lint rule banning eval() fires on a comment. The rule finds a pattern in bytes regardless of context - code, comment, or string. The scanner does not know you are describing a function. It knows the pattern is present.

This is not a bug. It is the correct behaviour. Deterministic tools cannot safely execute arbitrary text to judge whether a pattern matters in context. So they scan. They trust the text.

What Machines Do to Your Pages

When an AI agent fetches your page, it reads the source.

Not the hero image. Not the animation. Not the hover state. The bytes.

The <title> tag, the meta description, the JSON-LD block in <head>, the MX governance fields - these are what the machine reads. The visible surface and the machine-readable surface are different artefacts of the same file.

A page can score well for design and leave a machine with nothing useful to cite.

The Invisible Contract

Every file has two audiences.

The human sees the rendered surface. The machine sees the source. Most content is authored for one. MX is the discipline of authoring deliberately for both.

A "@type": "Article" declaration in JSON-LD does not change what a human sees. It changes what machines know. The typed assertion travels in the source. Any agent that reads the file reads the assertion. Invisible to visitors. Legible to every machine that processes the page.

That is not a side effect. It is the point.

The Governance Consequence

When a regulator asks what an AI read when it cited your content, the answer is the source. Not the rendered page. The source.

The JSON-LD, the provenance sidecar, the governance fields - these are the evidence layer. Legible to any machine that processes the file. Invisible to any human who reads the finished article without examining the markup.

When you declare a file's provenance, its publisher, its content policy, you are making a machine-readable record. The record travels with the file. Any machine that reads the file reads the record. Auditors walk the chain without asking you to curate the answer.

The Question to Ask

Before you publish anything, ask: what will the machine read?

Not what will the human see. What will the machine read.

The text content. The structured data. The metadata. The carrier fields. These are what agents, crawlers, indexers, and regulators retrieve. The hero banner is for the visitor. The source is for the machine.

That gap - between what humans see and what machines read - is what MX closes.
