Agent Ready Is Three Verbs, and an Honest Visitor

1 November 2026 · Tom Cranstoun · 6 min read

On 10 November, The Verge reported that Meta's Muse agent could no longer pull listings from eBay. eBay's spokesperson said the company has "restricted agent access in certain cases" and is talking to possible partners. The same day, the log-analysis firm Oncrawl noted that ChatGPT Agent and Muse browse with an ordinary Chrome user agent but now sign their requests with a Signature-Agent header. So one site is shutting agents out while the agents themselves start saying who they are. If you run a site, you probably don't know which agents yours lets in, or why.

Miriam Schwab has written two posts on the Elementor blog that get "agent ready" right. The first, What agent ready means, puts it in three verbs: "An agent ready site makes three things easy for an agent: reading, querying, and acting." The second, What agents actually use, walks the mechanisms one at a time and is candid about how few are standards yet.

I agree on the three verbs, and even more with her point about identity. I want to say what an audit owes a site owner once you accept both.

Read, Query, Act

Reading is mostly solved, and accessibility solved it. An agent that falls back to browsing reads the same tree a screen reader does, so real headings and buttons that are buttons help a blind visitor and a machine through the same code. A fetcher that discards the layout needs the answer in the HTML it receives, not painted in later by a script.

Querying is asking a specific question and getting a structured answer: is this in stock in size 9, when is the next event. Structured data does some of this; a site's MCP server does more, once someone has connected it. Schwab notes that most fetchers drop every script block on the way to text, so anything that lives only in markup goes unseen by many agents. Put it in the visible text as well.

Acting is where the web is furthest behind. An agent that finds a form field by its position breaks when the design changes. A labelled field helps. A named action with a description and typed inputs keeps working however the page looks, and WebMCP exists to provide exactly that.

An AX audit reviews the reading and querying side page by page: what an agent receives, how it's structured, and what context comes with it. Whether an agent can finish a task, such as getting through checkout, needs separate testing, which is a different Tityra service, the AX Journey Audit. What the three verbs give me is a cleaner way to report it: the first page should say which of the three an agent can do on this site, and which it can't, with the evidence behind each.

The visitor has to be honest too

A bot introduces itself with a user-agent string, a line of text it writes about itself. Nothing stops a script calling itself GPTBot. So when a readiness scanner tested Schwab's site while pretending to be GPTBot, her bot defence noticed the request didn't come from OpenAI and refused it. The scanner then reported that her site blocks AI agents. The site did the right thing; the scanner published a false positive.

I take that as a rule for anyone who audits sites, us included. An auditor that impersonates a vendor's crawler isn't measuring if a site is open to agents. It's testing the bot defence, and then mislabelling the answer. There's a fair question underneath, what a site's rules do with a given name, but the verdict has to say what a refusal means. A vendor-named request from the wrong address, refused, is "blocks impersonators". It becomes "blocks agents" only when an honest request, one that names its operator and links to a page about itself, is refused as well. The next step, which Schwab also names, is Web Bot Auth: the agent signs each request and the site checks the signature against a published key. An auditor should sign its own requests as soon as it can, and say so.

That step has stopped being theoretical. Once ChatGPT Agent and Muse sign their requests, a site can tell them apart from a script that just borrows their names. Defaults matter here too. Engadget reports that since 15 September, new domains on Cloudflare allow search crawlers but block AI training bots and agents on pages that carry ads, unless the owner changes the rules. So a site can be turning away shoppers' agents without anyone there having decided to. Read your logs for the Signature-Agent header and check what your bot settings do with it, then decide on purpose.

No cloaking

Schwab's second rule is the one SEO taught everyone the hard way: showing a bot a different page from the one people see got sites penalised. Her line is that "agent files and markdown versions of pages need to match what people see."

Markdown twins of pages are spreading, served at a .md URL or by asking the normal one for text/markdown. They're a fraction of the HTML's size, and they open a quiet way to say one thing to people and another to machines, by intent or by a stale copy nobody regenerated. An audit should fetch the twin by every route the site offers and compare the words: headings, prices, dates, claims. A twin that says something the page doesn't is a finding, with both excerpts attached. The same applies to llms.txt, and to a negotiated response that omits the header saying it varies by request, which is how a person ends up downloading markdown.

What we add

Agreeing with a definition is cheap. What we add is the evidence.

Every finding in an AX audit says how it was reached: which request was made, as whom, what came back, and when. A verdict that a site supports querying names the server that answered and the tools it listed. A verdict of "blocks impersonators" shows the honest request that got through beside the spoofed one that didn't. That's Machine Experience applied to our own output: the next reader, human or machine, gets what they need to check the claim, and a site owner who doesn't trust us can run the same checks without us.

Preferences get the same treatment. Whether a site lets agents read it and whether it lets anyone train on it are separate decisions, and owners should state both. An audit should read what a site declares, in robots and in headers, and show it beside what's served. It shouldn't grade the declaration, and it should never present any of this as a certificate. Agent ready is a property of a site on a day, measured by a named method, and the next deploy can change it.

Pull a day of your server logs, look for the Signature-Agent header, and compare what you find with what your bot settings say they allow. If you'd rather have that evidence written up for you, with every request named and every finding checkable, that's what an AX audit gives you, from a visitor who told you who it was.
