Load the Answer, Not the Estate

22 June 2026 · Tom Cranstoun · 6 min read

There is a moment, watching an AI agent work a long job, where it starts to get worse. Early on it is sharp. It reads a file, makes the right call, moves on. A while later it is re-reading things it already read, second-guessing a decision it got right, and reaching for a tool it used correctly twenty steps ago as though seeing it for the first time. Nothing crashed. It just went dull.

The instinct is to give it a bigger window: more room to remember, more context to hold. And the window did get bigger. The agent did not get sharper, because the problem was never how much it could hold. It was what ended up in there.

The window is the whole vote

A model working inside a repository is stateless between turns. It does not carry a private memory of the job from one step to the next. The only thing steering its next move is what is in front of it right now: the conversation, the files it has opened, the output of every command it ran. That is the entire ballot. Every right next step and every wrong one is decided by what sits in the window at that instant.

So the contents matter more than the size. Fill the window with the actual question and a clean, dense statement of what is true, and the next move is likely to be right. Fill it instead with the raw scrollback of a search, half a build log, a directory listing, and the JSON some chatty tool dumped on its way past, and the agent is now voting on clutter. It does the real work surrounded by noise, and the noise wins more often than you would like.

There is a worse version. If the window is a history of the agent making a mistake, correcting it, making another, correcting that, then the most likely next move is one more mistake, because that is the pattern the history is teaching. A polluted window does not merely dilute the signal. It trains the wrong reflex.

Keep the window small on purpose

Everything that actually helps here is a version of one idea: keep the window small on purpose, and make what is in it count. This is the ground MX has stood on from the beginning, so let me say it in those terms. Three moves.

A cog is compaction you can hand to the next agent. A cog is a plain file, readable by a person and a machine alike, that states what something is, how it relates to everything else, and what is safe to do with it. That is the compressed artifact, written down once. Instead of letting an agent reconstruct the state of a system by crawling it, and burning half its window doing so, you hand it the cog and it reads the conclusion. A well-kept repository greets a fresh session exactly this way: a short, generated brief that says, in effect, read this, do not re-derive the state from scratch. The agent begins in the clean part of the window with the answer already in hand, instead of grinding its way toward the answer through the dull part.

A script's verdict keeps the evidence out of the window. The most expensive thing an agent can do is reason its way to a fact a script already knows. If a rule can be checked mechanically, a check a script can do, a script does, and the agent reads one line, pass or fail, rather than loading the evidence and inferring the verdict for itself. The script votes; the window stays clean. Every deterministic check is a token cost you never pay and a divergence you never risk, because two different models cannot disagree about a number a script computed. Inference is the thing you are trying to keep out of the window. A check is how you keep it out.

A self-describing repository serves the answer, not the estate. A repository that describes itself, a registry of what every part is, a graph of how the parts connect, a single machine-readable index it can serve in one fetch, lets an agent load the answer to "what is here and how does it fit" instead of opening a thousand files to infer it. And when a sub-question genuinely needs a heavy search, that search can be sent to a separate, fresh window which does the digging and returns one sentence: the file you want is here. The agent that asked never pays the token cost of the search. It pays the cost of the answer. Fan the work out, keep the conclusion, throw the scrollback away.

The discipline, made structural

None of this is a trick of phrasing. You cannot prompt your way out of a window full of noise, and a bigger window does not save you, it just lets you load more noise before it shows. A bad search becomes a bad plan becomes a long run of bad work, whatever the model, however large the window. The thinking still has to be good. What MX changes is what the agent has to read to do the thinking: the answer, stated plainly, instead of the whole estate, waiting to be inferred.

That is the line worth holding onto. A bigger context window raised the ceiling on what you can load. It did nothing to change what you should. The cog is the answer written down. The check is the inference taken out. The self-describing repository is the estate that hands you its conclusion instead of making you crawl for it. Put those together and the agent spends its window on the job in front of it, not on rediscovering the ground it is already standing on.

The cheapest token is the one the agent never has to read, because something already did the reading, and wrote down what it found.
