Edge Agents Need State They Can Check

11 October 2026 · Tom Cranstoun · 5 min read

Moving inference to the edge cuts latency but strips the agent of verifiable context. That trade is worth making. It's also worth naming what you've traded.

In Once Agents Talk, AI Is a Distributed Systems Problem I took Tony Seale's point that once agents talk to each other, AI becomes a distributed systems problem. Push the agent out to a device, a branch or an edge node, and those problems get sharper. A central agent that doubts a document can fetch the master copy. An edge agent was put there so it wouldn't have to.

What Goes Wrong

The edge agent decides on what it holds. A cached page. A file synced last night. A message relayed by a peer.

Stale local decisions. The copy was superseded an hour ago, and nothing in the bytes says so. A price fetched then looks exactly like one fetched a second ago.

Provenance you can't trace back. The payload arrived, so you know which pipe it came down. You don't know who wrote it, and the author isn't there to ask.

Agents acting on conflicting assumptions. Two agents hold different versions of the same policy. Each acts correctly on its own copy, and their actions disagree. Neither can see the other's input.

Metadata That Travels With the Payload

The fix is state the agent can check where it stands, without the round trip you moved to the edge to avoid.

MX puts that state in the file. A cog is any file carrying MX metadata, and those fields go wherever it goes. The identity fields tell the agent what the document is, who wrote it, when it changed, and where the master copy lives. The genuineness family does the harder work, and each field defers to a standard that already exists. proofOfAuthorship follows W3C Verifiable Credentials and Signed Exchanges. integritySignature follows RFC 9421 and Subresource Integrity, with a digest the agent recomputes over the body. provenancePedigree borrows from W3C PROV-O and C2PA to record the chain back to the source.

None of those checks needs the origin to be reachable. That's how provenance can carry back to the authoring cog: through declared integrity fields and signature standards the agent can verify on its own.

The limits matter just as much.

Provenance doesn't travel on every transaction automatically. Somebody has to declare the fields and sign. A payload that leaves without them arrives without them, and the honest reading is "unverified".

The registry records attestations. It doesn't reconcile state. A registry can tell an agent that the owner published this copy unaltered. It can also say a newer version exists. That check costs one lookup, so you decide which decisions earn it. When two agents disagree, MX shows each which version it holds. Settling the disagreement stays with the agents and the people who run them.

Skills Suggest, Action-Cogs Execute

Checkable inputs are half of it. The other half is what the agent does next.

A skill is prose in a context window, interpreted by a probabilistic model, and two runs can take it differently. That's fine for guidance. It's the wrong home for "refuse to act on a copy older than the attested version".

An action-cog runs. Its actionType says how: scripted means an embedded script, same inputs and same outputs; sop means a model reads the steps and performs them; hybrid splits the work between the two. Its security block declares the risk, whether the action can be undone, and the guardrail in front of anything irreversible. Put the threshold and the refusal rule in a scripted action-cog. At the edge there's no central reviewer to catch a model that read the paragraph differently this time.

Confidence and Logs Don't Close the Gap

Edge deployments love a confidence score and a log line. Keep both. Just don't mistake either for provenance.

Confidence tells you how sure the model is; provenance tells you whether to believe it. A 0.94 on a stale copy is a precise number about the wrong fact. I made the longer case in my post on confidence scores and provenance.

A log is the system's own account; provenance is a chain of custody someone else can check. The agent's log is the agent vouching for itself. A provenance record names the action-cog, its version, the input and the policy, so someone downstream can check the decision without taking the agent's word.

If You're Deploying Edge Agents

Ask your publishers for authorship and integrity fields, and verify them before the agent trusts a payload. Write down which decisions justify a currency lookup. Move thresholds and refusal rules out of skills and into scripted action-cogs. Record provenance beside the confidence score. Put a named human in front of anything that can't be undone.

Keep the latency win. Give the agent something it can check.
