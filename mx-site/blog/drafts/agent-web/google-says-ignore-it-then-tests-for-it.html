Google Says Ignore llms.txt, Then Tests for It

30 June 2026 · Tom Cranstoun · 5 min read

Google Search's guidance on AI features is plain: "You don't need to create new machine readable files, AI text files, or markup to appear in these features" (Google Search Central). Most teams read that as permission to skip llms.txt, and for Search they're right.

Then Google's Lighthouse, the audit engine behind PageSpeed Insights, added an Agentic Browsing category, and one of its audits checks llms.txt (Chrome for Developers). Google says you don't need it, then checks it.

That's less of a contradiction than it looks. The two are answering different questions, and the difference shows the purpose of llms.txt.

What Each Side Is Saying

Search's guidance answers one question: do you need a special file to appear in Google's AI features? No. Those features read your pages. A file at the root won't get you cited, and it'sn't a ranking signal.

The Lighthouse audit answers a narrower one: if you publish an llms.txt, is it a usable Markdown file? It fetches /llms.txt from the site root. A missing file (any 4xx) is marked not applicable, because publishing one is optional. A server error or a 429 fails. A file that comes back has to contain an H1, a Markdown link and 50 or more characters (Lighthouse llms.txt audit source). It checks that the file is well formed, not what it does for you.

Neither statement says llms.txt changes how you rank or how often you're cited. Read together, they say: optional, and if you do it, do it properly.

What llms.txt Is Not

Most writing about llms.txt frames it as a training-data play: publish a structured description of your site, training pipelines find it, and future models know your name and what you do. There's no evidence that publishing one shapes what a model learns. Even if it did, you would be betting on whether a crawler fetched the file, whether a pipeline kept it, and whether it landed before a model's cutoff, none of which you can see or control.

It'sn't a search lever either. The Search guidance above says so directly.

What It Is Good For: An Index at Query Time

A person tells an AI: "Research this company and tell me what they do." The AI can work through the homepage, the about page, the services pages and the blog, or it can start from a single curated file that says what the company does and links to the pages that matter.

When a tool reads that file, it has a shorter path. It still has to read the pages it cites, but it knows where to start. That's the modest, real value of llms.txt: a reading guide for the tools and agents that choose to use it. Some developer tools and agents fetch it; many answering systems go straight to the pages a question needs and never ask for it.

The most reliable reader is you. When your team asks an assistant about your own site, hand it the llms.txt first. As an illustration, not a measurement: a summary of a few hundred tokens can replace several full pages the assistant would otherwise read to find the same facts. How much it saves depends on the site, the question and the tool.

Keep It Honest

Because it's a summary, llms.txt can drift from the pages it describes. A stale one is worse than none: it points machines at pages you have dropped, and it states things the pages no longer say. The value is in keeping it current, which is easiest when your build generates it from the same source as the pages and the sitemap.

How to Think About It

robots.txt controls access. It tells crawlers what they're allowed to read.

llms.txt is different. It's an index: if you're trying to understand this site, here is where to start, here is what we do, here is where the details live.

Treat it as optional and low-cost. Publish one if your build can produce it cheaply, and do the pages, the structured data and the Markdown versions of your pages first, because those are what answering systems read.

The Checklist

If you own an llms.txt or are deciding whether to create one:

  1. Do the pages first. Server-rendered content, accurate metadata and structured data matter more than any index file.
  2. Write it as Markdown. One H1 naming the site, a short summary, and Markdown links in [text](url) form to the pages you stand behind.
  3. Serve it as text. text/plain or text/markdown, with a 200, from the file itself. No HTML wrapper, no catch-all rewrite, no challenge page. Leave it out of sitemap.xml.
  4. Point to it. <link rel="describedby" href="/llms.txt"> in the <head> of each page, or the matching Link header, as the llms.txt proposal describes.
  5. Keep it current. Generate it, don't hand-edit it, and never let it say anything the pages don't.
  6. Run the check. Lighthouse's Agentic Browsing category reports the llms-txt audit. Passing it doesn't affect rankings or citation; it tells you the file is well formed.

You won't know whether your llms.txt influenced a model. You can know whether it's well formed, current and useful to the tools you use yourself. Start there, and keep your expectations to that.
