Introducing MX Cogs: Modular Capabilities for the Robot-First Web

13 June 2026 · Tom Cranstoun · 5 min read

The web is changing. AI agents are becoming first-class citizens alongside humans. But most tools aren't ready for this shift - they're designed for humans to read, not machines.

MX Cogs change that.

What is MX?

MX stands for Machine eXperience Engine. It's a framework built on a simple principle:

Patterns that work for AI agents also work for humans.

This is the Convergence Principle. When we design for machines - semantic HTML, explicit state, structured metadata - we inadvertently improve things for humans too. Screen readers benefit from semantic HTML. People with cognitive disabilities benefit from explicit state. Everyone benefits from clear documentation.

MX takes this insight and builds on it.

The Engine and Its Cogs

Think of MX as an engine. Every engine needs components to do work. In MX, these components are called cogs.

Concept MX Equivalent
Engine MX (Machine eXperience Engine)
Cogs Modular capabilities
Fuel Content, data, user intent
Output Robot-First experiences

Each cog does one thing well. Together, they power the Robot-First Web.

What Makes a Cog?

A cog is a markdown file with YAML frontmatter. That's it.

---
name: llms-txt
version: 0.1.0
description: Generate and validate llms.txt files

created: 2026-02-06T12:19:00Z
modified: 2026-02-06T12:19:00Z
author: MX

execute:
  command: mx cog llms-txt
  actions:
    - name: generate
      description: Generate llms.txt from a website
      usage: mx cog llms-txt generate <url>

mx:
  convergence: true
  accessibility: true
  semantic: true
---

# llms-txt

Human-readable documentation here...

Machine-readable metadata. Human-readable documentation. One file.

Any AI agent can parse the YAML and understand:

  • What this cog does
  • How to execute it
  • What inputs it needs
  • What outputs it produces

Any human can read the markdown and understand the same things.

Convergence in action.

The MX Section

Every cog declares its alignment with MX principles:

mx:
  convergence: true    # Benefits both humans and machines
  accessibility: true  # Improves accessibility
  semantic: true       # Uses semantic structures

This is MX practising what it preaches - machine-readable metadata about machine-readability.

If a cog can't answer "yes" to convergence, it should explain why in the documentation. Not every tool benefits both equally, but we should be intentional about it.

Core Cogs

We've started with four cogs focused on the Robot-First Web:

llms-txt

Generate and validate llms.txt files - the new standard for helping AI agents understand websites.

mx cog llms-txt generate https://example.com
mx cog llms-txt validate https://example.com/llms.txt

schema

Validate Schema.org structured data. Because machines need semantics.

mx cog schema validate https://example.com
mx cog schema extract https://example.com

clarity

Test documentation clarity. If AI struggles to understand docs, humans probably do too.

mx cog clarity test ./README.md

pricing

Catch the £200,000 errors before they erode trust.

mx cog pricing validate https://shop.example.com

The pricing cog exists because of a real example: an AI agent researched river cruises and returned prices of £200,000+ per person. Actual prices were £2,000-£4,000. European number formatting plus missing guardrails equals trust erosion.

Cog Categories

Cogs come in three categories:

Core (mx-core)
Focused on Robot-First Web principles: llms.txt, Schema.org, documentation clarity, data validation.

Capability
General capabilities: email, calendar, browser automation, camera access.

Integration
External service integrations: GitHub, Slack, Discord, and more.

The existing tools you use (email clients, browsers, APIs) become cogs. The engine (MX) orchestrates them.

Why This Matters

We're at an inflection point. AI agents are becoming primary consumers of web content - ~28% of Googlebot's traffic now comes from AI crawlers. Over $156 billion has been invested in generative AI search technology.

But most websites aren't ready. They're designed for humans only, with:

  • Non-semantic HTML
  • State hidden in JavaScript
  • Toast notifications that disappear
  • Prices without structured data

These aren't new problems. Blind users have lived with them for decades. Now AI agents are exposing them at scale.

MX Cogs provide the tools to fix this. Not just for machines, but for everyone. The Convergence Principle means what we build for AI agents benefits humans too.

Getting Started

  1. Explore the cogs: Read the YAML frontmatter. It tells you everything.

  2. Run a cog:

    mx cog llms-txt validate https://your-site.com/llms.txt

  3. Build your own: Follow the cog specification and cog guide.

  4. Share: Cogs are markdown files. They're meant to be shared, forked, improved.

The Vision

MX isn't just a tool. It's a way of thinking about the web.

Machines are first-class citizens now. They read pages, interpret structures, enforce rules, generate experiences. If we don't design for them, we're designing for a world that no longer exists.

But here's the beautiful part: designing for machines benefits humans. The Convergence Principle isn't a compromise - it's an upgrade for everyone.

MX Cogs are how we build that future. One modular, self-describing, machine-readable component at a time.

"Design for machines. Benefit humans. Advance both." ⚡
