## Slide 2: The Problem

**Machines cannot reliably read or act on human documents.**

This is not a web problem. This is a civilisation‑scale document problem across:

- PDFs · Word files · Emails · Manuals · Contracts · Policies
- Reports · Blueprints · Scientific papers · Medical records
- Manufacturing specs · Government archives · CMS outputs · Knowledge bases

Every machine — robots, LLMs, autonomous systems, industrial controllers, sovereign AI appliances — hits the same four structural failures:

- **Wasted inference** — machines repeatedly re‑compute meaning
- **Energy waste** — inference on ambiguous documents becomes an energy problem
- **Extraction errors** — ambiguity forces machines to guess
- **No provenance** — no cryptographic verification of origin or integrity

This is the missing infrastructure layer for the machine age.

## Slide 4: What MX OS Is

**A universal, document-native runtime layer for machines.**

Three pillars:

- Structured Data — Schema.org, JSON-LD, XMP, CSVW
- Accessibility & Semantics — WCAG, semantic HTML, tagged PDFs, structured DOCX
- Explicit Intent — machine-readable state + action blocks

Two document types: Info-docs describe · Action-docs execute

Cogs ≠ skills:

- Cogs are durable, portable, self-describing documents
- Skills are ephemeral instructions tied to specific platforms

Safe failure mode: When in doubt, do X — prevents machine improvisation.

MX OS is format-agnostic: If it's a document, MX OS can make it machine-native.
