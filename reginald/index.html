The Problem

AI inference systems generate wrong answers to questions that already have documented answers. This happens because documentation was designed for humans reading web pages — not for machines parsing structured data.

How It Works

MX-Reginald is DNS for machine-readable documentation. It maps COG identifiers to publisher-hosted content URLs. MX-Reginald does not host content — each publisher serves their own COGs from their own domain.

Two-Layer Trust

Publisher Signs Content

The publisher cryptographically signs their COG, proving "I wrote this and it is current." The signature travels with the content.

Registry Signs Pointer

MX-Reginald signs the pointer record with Ed25519, proving "this document was registered, validated, and conforms to specifications."

Pure resolver, not a host. MX-Reginald resolves identifiers to URLs — it never stores or caches content. Publishers retain full control of their documentation and can update it at any time.

What Is a COG?

A COG is a markdown file with YAML frontmatter. No proprietary format. No binary encoding. No special tooling required. A .cog.md file that any text editor can open and any AI system can parse.

---
title: "Rancilio Silvia Pro X"
description: "Dual-boiler espresso machine with PID temperature control"
author: "Rancilio Group"
version: "2.1"

mx:
  status: active
  contentType: product
  tags: [espresso, dual-boiler, pid]
  maintainer: "product-team@rancilio.com"
  reviewCycle: "quarterly"
  expires: 2026-07-01
---

# Rancilio Silvia Pro X

The Silvia Pro X is a dual-boiler espresso machine...

The YAML frontmatter is for machines. The markdown body is for humans. Same file, both audiences served.

The Dual Meaning

LayerFull NameWhat It Proves
CertificateCertificate of Genuineness"This document is real"
ContractContract of Governance"Someone keeps this accurate"

Every COG carries both layers. The Certificate tells an AI agent whether to trust the content. The Contract tells it who is responsible for keeping the content current — with a named maintainer, a review cycle, and an expiry date.

Two Types

Info-Doc

A COG without an action block — documents, describes, certifies. The single source of truth for a product, API, or specification.

Action-Doc

A COG with an action block — validates, generates, extracts, analyses. A Standard Operating Procedure that executes itself. The document is the programme.

API

Base URL: https://reginald.allabout.network

Read Endpoints Public

  • GET /index.json Full registry index
  • GET /api/v1/stats.json Registry statistics
  • GET /api/v1/publishers.json Registered publishers
  • GET /api/v1/namespaces.json Namespace directory
  • GET /api/v1/namespaces/{ns}/cogs.json COGs in a namespace
  • GET /cogs/{ns}/{name}/latest.json Pointer record (latest version)
  • GET /api/v1/public-key.pem Registry Ed25519 public key
  • GET /llms.txt AI-readable registry summary

Write Endpoints Auth Required

  • POST /api/v1/subscribe Create Stripe checkout session (new publishers)
  • POST /api/v1/register Register or update a namespace (Bearer token)
  • GET /api/v1/publisher/status Check subscription and listing status (Bearer token)
  • POST /api/v1/publisher/token/rotate Generate new API token, revoke old (Bearer token)

Authentication

Read endpoints require no authentication. Write endpoints require a Bearer token issued during subscription:

Authorization: Bearer reg_your64hexcharshere...

Tokens are generated at subscription time and can be rotated via the token rotation endpoint. Token format: reg_ prefix + 64 hex characters.

Get Started

  1. Choose Your Integration

    WordPress: Install the MX Cogify plugin — it handles manifest generation, Schema.org, and MX-Reginald registration automatically.

    Adobe EDS: Copy the mx-cogify block into your project. Use the CLI tool for registration.

    Any Platform: Host a .well-known/mx-cogs.json manifest on your domain. MX-Reginald's verification pipeline crawls it.

  2. Subscribe

    Call POST /api/v1/subscribe with your namespace and email. Complete the Stripe checkout. Your API token is generated automatically.

    curl -X POST https://reginald.allabout.network/api/v1/subscribe \
  -H "Content-Type: application/json" \
  -d '{"namespace":"your-namespace","email":"you@example.com"}'

  3. Register Your Namespace

    Use your API token to register. MX-Reginald validates your manifest, signs the pointer records, and makes your COGs queryable worldwide.

    curl -X POST https://reginald.allabout.network/api/v1/register \
  -H "Authorization: Bearer reg_your_token..." \
  -H "Content-Type: application/json" \
  -d '{"namespace":"your-namespace","domain":"yoursite.com","manifest_url":"https://yoursite.com/.well-known/mx-cogs.json"}'

  4. Verify

    Check your registration status and see your COGs in the registry.

    curl https://reginald.allabout.network/api/v1/publisher/status \
  -H "Authorization: Bearer reg_your_token..."
