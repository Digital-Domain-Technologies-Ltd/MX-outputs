# Co-Directors Report — PDF Pipeline Consistency

**7 March 2026 — Evening**

## Summary

Short, focused session to harden the PDF build pipeline. After regenerating Chapter 0 with pull quotes, Tom flagged that tables were cramped and headings were stranding at page bottoms. We diagnosed the root cause (missing LaTeX packages and no heading protection), applied fixes, then audited all PDF build configurations to ensure consistency across the entire pipeline.

The key insight: widow/orphan penalties (`\widowpenalty=10000`) only prevent single-line stranding. To stop headings appearing at the bottom of a page with no body text following, you need `\needspace` with `\pretocmd` to reserve vertical space before every heading level.

## What Changed

### Heading protection (all PDF configs)

Added `etoolbox` package and `\pretocmd` heading protection to all four LaTeX metadata configurations:

- `\pretocmd{\section}{\needspace{8\baselineskip}}{}{}` — sections need 8 lines
- `\pretocmd{\subsection}{\needspace{6\baselineskip}}{}{}` — subsections need 6 lines
- `\pretocmd{\subsubsection}{\needspace{5\baselineskip}}{}{}` — subsubsections need 5 lines

If the remaining page space is less than the threshold, the heading moves to the next page.

### Table readability (all PDF configs)

Standardised table spacing across all configurations:

- `\setlength{\tabcolsep}{4pt}` — column padding
- `\renewcommand{\arraystretch}{1.3}` — row height multiplier

### Kindle config remediation

The Kindle metadata (`metadata-kindle.yaml`) was missing table packages, widow/orphan prevention, and heading protection entirely. Added all packages and settings to match the other configurations.

### Build scripts updated

Updated `package.json` PDF build scripts to use `metadata-chapter.yaml` instead of bare inline flags, ensuring standalone chapter PDFs get the same LaTeX treatment as full book builds.

## Technical Note
