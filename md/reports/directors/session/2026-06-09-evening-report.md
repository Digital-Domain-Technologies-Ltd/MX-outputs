# Co-Directors Report - The documentation graph reaches 100% connected, with a gate to keep it there

**Date:** 9 June 2026 - Evening
**Segment:** evening (since 5pm)

---

## Summary

Our internal knowledge - the cogs, manuals, specifications, and decision records that machines and people both read - is only as useful as it is navigable. This session took that graph from roughly three-quarters connected to fully connected: every document now links to the rest by a real, declared relationship, with no orphans and no dead references. We removed two stale files, connected the documents that were adrift with honest links rather than cosmetic ones, and then added an automated gate that refuses any push which would leave a real document stranded. The day's documentation work shipped in four commits, and the cache was cleared so the public site reflects it.

---

## What Was Done

### 1. The documentation graph, made whole

We measured the internal documentation as a graph and found it was fragmented: a large share of documents had no machine-readable relationship to anything else, and a set of references pointed at things that no longer existed. We worked through it in two passes. First we cleared every broken reference - links written as prose concepts rather than real documents - so nothing points at nothing. Then we connected each genuinely stranded document with a true relationship to the document it actually belongs with: decision records to the decision index, manuals and tools to their subjects, the reference copy of the cog specification to its canonical source. Demonstration files and one generated catalogue, which exist to teach the format in isolation, were marked as out of scope rather than forced into the graph - linking them would have spoiled the very thing they teach. The result is a graph where every real document is reachable, with no broken references.

### 2. A gate so it stays that way

Connectivity that is achieved once but not enforced drifts back. We added a check that runs automatically before every push: if any tracked document has been left disconnected, the push fails and names the file, telling the author to add a real relationship or, if it is a demonstration, to exclude it. The check is also part of the standard test run. This turns a one-time cleanup into a standing guarantee, and it carries forward as a capability we can apply to a client's own document estate.

### 3. Two stale files removed, one self-knowledge file fixed at source

We removed an out-of-date copy of an internal self-knowledge file that still carried a since-corrected account of the Frankfurt event, and an unwanted training-plan file. The live self-knowledge file is regenerated by a script; we fixed that script so its output now carries the relationship and the required descriptive fields it had been missing, which means every future regeneration is correct rather than needing a manual patch.

### 4. The day's documentation work shipped

Alongside the graph work, the session committed the day's earlier documentation effort: a local-model content control panel for managing site content without anything leaving the operator's machine, a set of cross-links tying the pitch, architecture, and operational-note documents to each other and to the artefacts they describe, and a house-language sweep that brings the wording into line across the corpus and corrects the Frankfurt account everywhere it appeared.

## By the Numbers

- Documents connected: from about three-quarters to **100%** (196 tracked documents, none stranded).
- Broken references: reduced to **zero**.
- Files removed: **two** stale files; **24** stranded documents connected with real relationships.
- Commits pushed this session: **four** (one to the outputs store, three to the hub), all passing every pre-push quality gate.
- New automated gate added: **one** (documentation connectivity), now blocking on every push.

---

## Why It Matters

The same discipline we sell to clients - that a document estate should be navigable, self-describing, and verifiable by a machine that arrives without context - now holds for our own. A regulator, an agent, or a new team member can walk from any internal document to everything it relates to. The connectivity gate means that guarantee does not decay as the estate grows, and the analysis behind it is a deliverable we can turn on a client's knowledge base.

---

## What Was Deliberately Left

The working tree carries substantial in-progress work from other sessions - the web-audit suite's audience-and-age-awareness feature, regulatory-regime data, and manuscript edits among them. This session committed only its own work, by explicit file, and left the rest untouched for the sessions that own it. That is the correct discipline, but it means the repository will look busy until those other strands are committed by their authors.
