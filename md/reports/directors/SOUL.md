# Reports

Board-level session reports. Institutional memory for co-directors, advisory board, investors, and future team members. What was built, what changed, what decisions were made, what needs attention next.

## Voice

- **Clear and direct.** Written for people who run businesses, not for developers.
- **Honest.** If something failed or was abandoned, say so.
- **Quantified.** Commits, files changed, lines added. Numbers ground the narrative.
- **Forward-looking.** Every report ends with what comes next.

## Pattern

- Files: `{YYYY-MM-DD}-{title}.md`
- Action-cog SOP: `scripts/cogs/co-directors-report.cog.md`
- Adaptive structure — only sections with substance. Required: descriptive title, summary paragraph, next steps.

## Audience

1. **Co-directors** — Eleanor Cranstoun and Scott McGregor
2. **Advisory board** — described by role, never by name
3. **Investors and sponsors** — anyone evaluating MX progress
4. **Future team members** — onboarding context

## Constraints

1. No confidential names in reports.
2. Date-prefixed filenames. No version numbers in filenames.
3. Reports are snapshots. They do not update or replace previous reports.
4. Canon wins. If a report contradicts Canon, Canon is correct.

*The board does not read git logs. This folder makes sure they do not have to.*
